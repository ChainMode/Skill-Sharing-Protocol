# 8. 版本管理

## 8.1 两段式协议版本（`MAJOR.MINOR`）

SSP 协议版本采用严格的两段式语法（与技能自身实现版本 `SkillDescriptor.version` 的三段式 SemVer 严格正交）：

- JSON 载荷字段格式：`MAJOR.MINOR`（例如 `"1.0"`），严禁包含 `PATCH` 段或前导零。
- HTTP 协议标识格式：`ssp/MAJOR.MINOR`（例如 `ssp/1.0`）。

| 版本段 | 变更类型 | 兼容性 |
|--------|---------|--------|
| MAJOR | 不兼容的线协议或安全契约变更 | 破坏性，需要消费者升级 |
| MINOR | 向后兼容的可选字段或能力扩展 | 同主版本前向/后向兼容 |

勘误、文档澄清与参考实现缺陷修复属于版本版次（Edition）治理，不改变线协议版本号。

## 8.2 兼容性与无状态协商规则

### 8.2.1 同主版本兼容性判定

定义：

- 消费者支持的协议版本：`X.Y`
- 描述符或索引声明的协议版本：`A.B`

兼容条件：

```
兼容 ⟺ A === X
```

消费者在读取 `SkillIndex` 或 `SkillDescriptor` 时单方面无状态判定兼容性；同时客户端 **MAY** 在 HTTP 请求头中携带 `SSP-Supported-Versions: ssp/1.0` 声明其支持的版本集合，服务端无需维护会话握手状态。

### 8.2.2 兼容性矩阵

| 消费者 | 描述符 | 兼容 | 备注 |
|--------|--------|------|------|
| 1.0 | 1.0 | ✓ | 完全匹配 |
| 1.0 | 1.2 | ✓ | 次版本前向兼容（忽略未知可选扩展） |
| 1.2 | 1.0 | ✓ | 次版本后向兼容 |
| 1.0 | 2.0 | ✗ | 主版本不同，返回 `VERSION_INCOMPATIBLE` |
| 2.0 | 1.0 | ✗ | 主版本不同，返回 `VERSION_INCOMPATIBLE` |

## 8.3 版本不兼容处理

当消费者检测到版本不兼容时，**MUST** 拒绝调用并返回 `VERSION_INCOMPATIBLE` 错误（见第 9 章）。

## 8.4 向后兼容保证

次版本（MINOR）升级 **MUST** 满足：

1. 不删除已有的必需字段
2. 新增字段默认为可选
3. 不改变已有字段的语义
4. 不缩小枚举类型的值域
5. 不增加已有接口的必需参数

## 8.5 文档版本目录

协议文档按版本组织：

```
docs/{lang}/specification/
├── draft/                    # 当前开发草稿
│   ├── 01-引言.md
│   ├── 02-术语与约定.md
│   └── ...                  # 每章一个独立文件
└── 2025-10-25/              # 已发布版本（以发布日期命名）
    ├── 01-引言.md
    ├── 02-术语与约定.md
    └── ...
```

Schema 定义同样按版本组织：

```
schema/
├── draft/
└── 2025-10-25/
```
