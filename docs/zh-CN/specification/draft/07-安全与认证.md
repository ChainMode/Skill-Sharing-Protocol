# 7. 安全与认证

## 7.1 概述

本协议提供三级访问控制和四种认证类型，技能提供者 **MUST** 根据技能特性选择合适的安全策略。

## 7.2 访问控制策略

| 策略 | 未认证发现 | 认证后发现 | 调用要求 |
|------|-----------|-----------|---------|
| `public` | ✓ 可见 | ✓ 可见 | 无需认证 |
| `restricted` | ✓ 可见 | ✓ 可见 | 必须认证 |
| `private` | ✗ 不可见 | ✓ 可见 | 必须认证 |

### 关键规则

- 当未认证请求访问 Well-Known URI 时，返回的 Skill Index **MUST NOT** 包含任何 `access === "private"` 的技能
- 当认证请求访问 Well-Known URI 时，返回的 Skill Index **MUST** 包含所有该认证身份有权访问的技能（包括 `private`）
- **端点级强制鉴权红线（禁止仅依赖索引隐藏）**：对于 `private` 与 `restricted` 技能，提供者 **MUST** 在描述符获取端点（`GET /skills/:id`）以及调用/状态轮询端点（`POST /skills/:id/invoke`、`GET /invocations/:id`）同时实施服务端认证与权限校验：缺失或无效凭据 **MUST** 返回 HTTP `401`（`AUTH_REQUIRED`），权限或 FayID 归属不匹配 **MUST** 返回 HTTP `403`（`PERMISSION_DENIED`）

## 7.2.1 密码学信任根与消费者 Default-Deny 门禁

- 提供者发布的 `SkillDescriptor` 与 `SkillIndex` **SHOULD** 携带 `proof`（RFC 8785 JCS 规范化字节流 + RFC 7515/8037 Detached Ed25519 JWS，`alg: "EdDSA"`），并在同源 `/.well-known/fayid` 暴露公钥锚点与授权 `origin`。
- 消费者 **MUST** 独立校验：
  1. `proof.kid` 前缀与 `provider.fay_id` 一致，且公钥在 `/.well-known/fayid` 中未吊销、未过期；
  2. `issued_at <= now < expires_at` 有限有效期窗口；
  3. 描述符 `endpoint.url`（或索引 `descriptor_url`）的 HTTPS Origin 与 `/.well-known/fayid` 声明的 `origin` 双向一致；
  4. Ed25519 Detached JWS 签名有效（即使经过可选注册表镜像缓存转发，仍须端到端验签）。
- **Default-Deny 门禁**：任何缺失 `proof` 或验签未通过的外部技能均标记为 `unverified`，消费者 **MUST NOT** 自动调用；对于篡改签名、吊销密钥或跨源劫持等硬性失败 **MUST** 一律阻断；仅无签名开发态技能在经由 Faying Protocol 获得人类原型（Human Prime）显式确认后方可单次试运行。

## 7.3 认证类型

### 7.3.1 API Key 认证

描述符声明：

```json
{
  "type": "api_key",
  "header": "X-API-Key"
}
```

调用时 **MUST** 通过指定的 HTTP Header 传递 API Key。

### 7.3.2 OAuth 2.0 认证

描述符声明：

```json
{
  "type": "oauth2",
  "oauth2": {
    "authorization_url": "https://example.com/oauth/authorize",
    "token_url": "https://example.com/oauth/token",
    "scopes": {
      "skill:invoke": "调用技能",
      "skill:read": "读取技能信息"
    }
  }
}
```

调用时 **MUST** 通过 `Authorization: Bearer <token>` Header 传递访问令牌。

### 7.3.3 自定义认证

描述符声明：

```json
{
  "type": "custom",
  "custom": {
    "instructions": "使用 HMAC-SHA256 对请求体签名，将签名放入 X-Signature header",
    "parameters": [
      {
        "name": "secret_key",
        "type": "string",
        "description": "用于签名的密钥",
        "required": true
      }
    ]
  }
}
```

### 7.3.4 无认证

```json
{ "type": "none" }
```

仅适用于 `access === "public"` 的技能。

## 7.4 安全最佳实践

技能提供者 **SHOULD** 遵循以下实践：

1. 生产环境 **MUST** 使用 HTTPS
2. API Key **MUST** 通过 Header 传递，**MUST NOT** 出现在 URL 中
3. OAuth 2.0 Token **SHOULD** 设置合理的过期时间
4. **SHOULD** 实施速率限制（Rate Limiting）以防止滥用
5. 敏感技能 **SHOULD** 使用 `private` 访问策略
6. **SHOULD** 在响应中包含 `X-Request-Id` 用于审计追踪
